# photosync

[English](README.en.md) | **Русский**

[![CI](https://github.com/Windemiatrix/photosync/actions/workflows/ci.yml/badge.svg)](https://github.com/Windemiatrix/photosync/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Медиатека «Фото» с Mac — обычными папками на Яндекс Диске, и обратно.**

Для тех, кто хранит фото в «Фото» на Mac (в том числе в iCloud) и хочет вторую копию, которую можно открыть без Apple: в браузере, в приложении Диска на Windows или Android. photosync — консольная программа для macOS. Она будет раскладывать фото и видео по папкам вида `2024/05-01 - Отпуск/IMG_0001.HEIC` и переносить новое в обе стороны: снятое на Mac — на Диск, добавленное на Диск — в «Фото». То, что уже лежит на Диске, повторно не загружается. Сначала программа показывает план и ничего не удаляет без вашего согласия.

**Ранняя разработка: синхронизация ещё не работает** (см. «Статус»).

## Статус

**В разработке, пользоваться пока нельзя.** Синхронизации ещё нет, ваши фото программа не трогает. Релизы `v0.x` выходят автоматически после каждого слияния, но содержат только каркас: работает одна команда, `photosync version`. Всё ниже описывает задуманное поведение.

Уже есть:
- исследования поведения macOS, «Фото» и Яндекс Диска, на которых построено устройство программы;
- каркас программы и автоматический выпуск: архив для Mac, контрольные суммы и аттестация происхождения;
- CI на macOS: тесты с детектором гонок, порог покрытия, линтер;
- в библиотеке [osxphotos](https://github.com/Windemiatrix/go-libs/tree/main/osxphotos): определение схемы и чтение фото и альбомов из копии базы «Фото» (`photosdb.Open`); папки и фильтры — следующими.

Дальше: чтение медиатеки «Фото» → сканирование Диска → план → загрузка и импорт → первая работающая версия.

Вопросы и идеи — в [Discussions](https://github.com/Windemiatrix/photosync/discussions).

## Как программа бережёт фото (как задумано)

- **Сначала план.** `photosync plan` показывает, что будет сделано, и ничего не меняет. Изменения — только с `--apply`.
- **База «Фото» читается из копии** и только на чтение. Менять медиатеку программа будет только через системный интерфейс «Фото».
- **Удаления — по вашему выбору.** Политику выбираете при настройке (`init`); пока выбора нет, программа ничего не меняет. `none` — удаления не переносятся; `quarantine` (рекомендуется) — файл на Диске уходит в `.photosync/quarantine` на 90 дней, объект в «Фото» — в «Недавно удалённые»; `propagate` — сразу в корзину Диска. Удаления из «Фото» подтверждаются системным окном macOS (одно окно на пачку).
- **Опасное подтверждает человек.** Перед необратимыми операциями нужно ввести в терминале их количество; массовые изменения (больше 50 объектов или 5 %) — то же или флаг `--allow-mass-changes`. `--yes` здесь не работает.
- **Откат.** Каждый запуск пишет журнал; `photosync undo --apply` откатывает последний запуск, кроме необратимых операций — их список виден в плане заранее.
- **Синхронизируются оригиналы**, включая Live Photo и RAW-пары.
- **Доступ к Диску и приватность.** Пароля Яндекса программа не видит: вход по коду на https://ya.ru/device. Приложение получает право читать и писать файлы на Диске (`cloud_api:disk.read`, `cloud_api:disk.write`). Сеть — только API Яндекс Диска, его хосты передачи файлов и вход Яндекса: без телеметрии, проверок обновлений и отчётов о сбоях. Токен лежит в `~/.config/photosync/tokens/` в файле с правами `0600`; его могут прочитать программы, запущенные под вашей учётной записью. Отозвать доступ: `photosync remote logout <имя>` или в настройках Яндекс ID.
- **Открытый код (MIT).** Тестовые данные обезличены и проверяются сканером утечек; тесты, которые меняют «Фото», запускаются только под отдельной тестовой учётной записью macOS.
- Повторный запуск без изменений ничего не делает; один Mac на одно облако; интерфейс на русском и английском.

Подробно: [Защита от потери данных](docs/architecture.md#5-защита-от-потери-данных).

## Что получится на Диске

```text
<ваша папка на Диске>/
  2024/
    05-01 - Отпуск/         ← альбом «05/01 Отпуск» в папке «2024» в «Фото»
      IMG_0001.HEIC
    05-14/                  ← снимки без такого альбома — по дате
      IMG_0002.JPG
```

Альбом-событие — это альбом вида `ММ/ДД Название` внутри папки года в «Фото»; файл, добавленный в такой каталог на Диске, попадёт в этот альбом.

## Как это будет выглядеть

Команд ещё нет, так задумано:

```text
photosync init           # настройка: папка на Диске, вход в Яндекс по коду, что делать с удалениями
photosync plan           # что будет сделано — ничего не меняет
photosync sync --apply   # выполнить план
```

Вывод `plan` появится вместе с командой: он покажет, что будет загружено на Диск, импортировано в «Фото», перемещено и удалено, и итоговые числа.

Запуск по расписанию — через стандартный механизм macOS (LaunchAgent); готовый файл настройки появится вместе с первой работающей версией.

## Зачем

Медиатеку можно выгрузить разово (`osxphotos export`, экспорт из «Фото», запрос данных у Apple), но получится односторонняя копия, которая сразу устаревает. photosync держит папки на Диске и «Фото» в согласии.

- **Копия, которую понимает человек.** Файлы лежат на Диске обычными папками и открываются без «Фото».
- **Не начинать с нуля.** Фото, уже выгруженные на Диск вручную, сопоставляются с «Фото» и повторно не загружаются.
- **Личная и общая медиатеки iCloud** раскладываются в разные папки Диска.
- **Первое хранилище — Яндекс Диск;** контракт хранилища от него не зависит, другие облака можно добавить позже.

## Чем отличается

- **rclone, Syncthing** синхронизируют файлы, но не видят медиатеку «Фото»: альбомы, Live Photo и RAW-пары для них — просто файлы в закрытом пакете.
- **[osxphotos](https://github.com/RhetTbull/osxphotos)** умеет выгружать из «Фото» и импортировать в «Фото», но каждое направление — отдельная команда; сводить изменения двух сторон и переносить удаления он не умеет.
- **photosync** сравнивает три состояния (прошлый запуск, «Фото», Диск), строит один план в обе стороны с альбомами и удалениями и откатывает последний запуск.

## Чего пока нет

- Общие альбомы не синхронизируются.
- Импорт сразу в общую медиатеку не проверен; если не получится, объект попадёт в личную, а отчёт отметит его для ручного переноса.
- Несколько Mac на одно облако не поддерживаются.
- Отдельной команды расписания нет: будет образец LaunchAgent.
- Только macOS и только Яндекс Диск.

## Требования (план)

- Mac с macOS 13 или новее, Apple Silicon или Intel. Запуск на macOS 13 ещё не проверен.
- Доступ к «Фото»: macOS спросит его при первом запуске. Может понадобиться и «Полный доступ к диску»: чтобы прочитать базу медиатеки, программа копирует её и читает копию только для чтения. Менять медиатеку (импорт, альбомы, удаление) она будет только через системный интерфейс «Фото». `photosync doctor` покажет, каких прав не хватает.
- `ffmpeg` — только если включите перевод неподдерживаемых видео в MP4.

Новые версии macOS поддерживаются после проверки на них.

## Установка

Работающей версии пока нет, ставить релизы `v0.x` незачем. Каждый выпуск — один архив для Mac (Apple Silicon и Intel); установка и проверка (контрольная сумма и `gh attestation verify` — подтверждение, что архив собран из этого репозитория) описаны в заметках к выпуску.

Обновление — так же, вручную: программа сама в сеть за обновлениями не ходит. Как удалить программу и её данные — в [docs/architecture.md](docs/architecture.md#9-установка-и-обновление).

Из исходников (нужны macOS и Go 1.27): `go build ./cmd/photosync`. Своя сборка не сможет войти в Яндекс: реквизиты приложения встраиваются только в релизные сборки.
